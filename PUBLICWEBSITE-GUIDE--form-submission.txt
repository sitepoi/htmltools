PUBLIC FORM SUBMISSION - INTEGRATION GUIDE
==========================================

STATUS: this is the implemented contract. It supersedes the earlier draft that
lived in PUBLICWEBSITE-REQUEST--form-submit-api.txt and
CMS-PROMPT--save-form-submissions.md (both removed).

THE URL
-------
  https://<CMS-HOST>/api/public/forms/submit

  <CMS-HOST> = the hostname of the CMS (the tenant's own domain,
  for example cms.example.com). It is NOT the website domain,
  unless both are served from the same host.

  Method : POST only
  Format : JSON
  Auth   : NONE - no login, no API key
  Limit  : body maximum 256 KB, maximum 4000 characters per field


PROCEDURE
---------
  1. Send one JSON POST to the URL.
  2. Read the HTTP status.
  3. Show the visitor a success or an error message.
  4. Done - there is no second call and no read access.


1. THE REQUEST
--------------
  fetch('https://<CMS-HOST>/api/public/forms/submit', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Accept': 'application/json'
    },
    body: JSON.stringify({
      cmsObjectType: 'contact-requests',   // OPTIONAL
      formTypeId: 'contact-form',          // OPTIONAL (label only)
      page: '/contact',                    // OPTIONAL
      submittedAt: new Date().toISOString(), // OPTIONAL
      gw_hp: '',                           // honeypot, keep empty
      folder: { name: '2026-11-07-vancouver-cemc-trial-exam-registration' }, // OPTIONAL, see FIELD RULES
      values: {                            // REQUIRED
        name: 'Ada',
        email: 'ada@example.com',
        message: 'Hello'
      }
    })
  })


2. THE ANSWER
-------------
  200  {"ok":true,"id":"...","folderId":"..."}  stored (or silently dropped as spam).
       An empty/absent folderId means the record was stored UNFILED: the folder
       could not be created, so it will not appear in the application's object
       list. The submission itself is not lost.
  400  {"ok":false,"error":...} validation problem, invalid destination, or a
       malformed folder declaration (INVALID_FOLDER_TARGET / FOLDER_TREE_INVALID)
  403  {"ok":false,"error":"ORIGIN_NOT_ALLOWED"}
  405  method not allowed (POST only)
  413  body too large
  429  {"ok":false,"error":"RATE_LIMIT_EXCEEDED"}
  500  {"ok":false,"error":"STORAGE_FAILED"}

  Only 200 means the submission was accepted.
  The response never returns the submitted data.


FIELD RULES
-----------
  cmsObjectType  optional. The application (cmsObjectType) that should
                 hold the submission. Send it only when the data belongs
                 to a specific application.
                 When omitted, the submission goes to the shared default
                 application: form-submission-uniconbaseapps

  formTypeId     optional. Human label of the form. It is stored with the
                 submission. It is NEVER a destination.

  page           optional. Path of the page that produced the form.

  submittedAt    optional. ISO date. The server writes its own time when
                 it is missing.

  gw_hp          optional honeypot. It must stay empty. A non-empty value
                 means a bot: the answer is 200 and NOTHING is stored.

  folder         optional. The folder the record belongs to (form channel,
                 same keys as the keyed write path, D-PFI-26/27, in force
                 since 29 Oct 2026). Send it as a sibling of values, never
                 inside values:

                   typeId: 'existing-folder-id'              // wins, no creation
                   folder: { name: 'my-form-folder' }        // top-level folder
                   folder: { tree: [{ name: 'a' }, { name: 'b' }] }  // a/b

                 Both may be sent TOGETHER and that is the resilient pattern: the
                 CMS uses typeId when it resolves and falls back to folder.name
                 (find-or-create) when it does not - so a page can carry an id it
                 hopes is current and still land in the right folder if the id is
                 stale, unknown or empty.

                 name creates the folder if it does not exist (the server
                 slugifies the name and generates the id) and reuses it when
                 it does; tree is find-or-created node by node from the app
                 root, max depth 5 and max 10 nodes, otherwise 400
                 FOLDER_TREE_INVALID. 'default-one-folder' is a UI sentinel and
                 is never a valid target. The declaration is consumed by the
                 CMS and is NOT stored on the object.
                 Why it matters: without a folder the object is still stored but
                 the CMS object manager lists strictly per folder, so the record
                 is invisible in the app UI. Omit folder only when the app
                 declares defaultFolderStructure or the platform fallback
                 (top-level YYYY-MM folder) is acceptable.

  nameTemplate   optional. The NAME of the stored object, rendered by the CMS
                 from the submitted values (D-PFI-30, 29 Oct 2026):

                   nameTemplate: '{{student_name}}'
                   nameTemplate: '{{student_name}} - {{exam}}'

                 Placeholders are the field names inside values; an unknown one
                 renders empty. The record then shows that text in the object
                 list, inside its folder, instead of a timestamp.

  objectName     optional. Final name as written; it WINS over nameTemplate.
                 Use it only for a fixed title that does not depend on the
                 answers. Send one of the two keys, not both.

                 Precedence: objectName > nameTemplate > the application's
                 formIntake.nameTemplate > the default
                 `<application> (<formTypeId>) - <receivedAt>`.
                 Neither key touches the object id or slug.

  values         required. A flat object of fieldName: textValue.
                 Every value is stored as text.
                 Do not nest objects inside values.

  Field names inside values are free. They become the field names of the
  stored submission.


HONEYPOT MARKUP (recommended)
-----------------------------
  <form id="contact">
    <input name="name" required>
    <input name="email" type="email" required>
    <textarea name="message"></textarea>

    <input name="gw_hp" tabindex="-1" autocomplete="off"
           aria-hidden="true"
           style="position:absolute;left:-9999px">
  </form>

  When submitting with JavaScript, read the form, move gw_hp to the
  payload root and keep it out of values:

  const formData = Object.fromEntries(new FormData(form).entries())
  const honeypotValue = formData.gw_hp || ''
  delete formData.gw_hp

  body: JSON.stringify({
    page: window.location.pathname,
    gw_hp: honeypotValue,
    values: formData
  })


ONE THING TO CONFIRM BEFORE GOING LIVE
--------------------------------------
  If the website runs on a DIFFERENT domain than the CMS, that domain
  must be on the CMS origin allowlist. Otherwise every submission gets
  403 ORIGIN_NOT_ALLOWED.

  Give the CMS side the exact site origin, for example
  https://www.example.com
  and it is added to the site configuration (websiteConfig.hostNames or
  formIntake.allowedOrigins).

  If the page is served from the CMS host itself, nothing has to be
  configured.


TEST BEFORE GOING LIVE
----------------------
  curl -i -X POST https://<CMS-HOST>/api/public/forms/submit \
    -H "Content-Type: application/json" \
    -d '{"page":"/test","values":{"name":"Ada","email":"ada@example.com"}}'

  Expected: 200 {"ok":true,"id":"..."}

  Then open "Form Submissions" in the CMS:
  the application appears with one row and all submitted values.
  Delete the test row afterwards.


ERRORS AND WHAT THEY MEAN
-------------------------
  ORIGIN_NOT_ALLOWED      the website domain is not allowlisted
  RATE_LIMIT_EXCEEDED     too many submissions from this visitor
  UNKNOWN_DESTINATION     the cmsObjectType you sent does not exist
  DESTINATION_DISABLED    that application refuses public submissions
  BODY_TOO_LARGE          the payload is bigger than 256 KB
  STORAGE_FAILED          the CMS could not store it, contact the CMS side


WHAT NOT TO DO
--------------
  - Do not put an API key in the page.
  - Do not call any read endpoint to confirm the submission.
  - Do not send a nested object inside values.
  - Do not name the destination with formTypeId.


WHERE THIS IS WIRED IN THIS REPO
--------------------------------
  The shared snippet lives in each public page that has a form (the
  contact, volunteer and join pages). It implements exactly the procedure
  above:

    var formApiEndpoint = 'https://<CMS-HOST>/api/public/forms/submit';

  Page attributes it understands:
    data-gw-form              marks the form (required)
    data-gw-form-type         sent as formTypeId (label only)
    data-gw-cms-object-type   sent as cmsObjectType (optional; when absent
                              the CMS default application is used)
    data-gw-form-endpoint     overrides the endpoint for that one form
    data-gw-form-status       the live region the message is written into

  It keeps the honeypot out of values, caps every value at 4000 characters,
  adds .gw-busy while sending, and writes is-ok / is-error into the status
  element. With no endpoint configured it falls back to the CMS platform
  bind, and in a local preview it says the service is not connected.

  Remaining setup on a site: put the real CMS host in formApiEndpoint, set
  cmsObjectType if the submissions belong to one application, and make sure
  the site origin is on the CMS allowlist.

  Wired today: endpoint
  https://futurebridgeacademyca.uniconhub.com/api/public/forms/submit, with one
  destination per page - contact-us-forms-uniconbaseapps (contact),
  apply-position-forms-uniconbaseapps (volunteer),
  form-submissions-uniconbaseapps (join, trial exam registration and any form
  without a more specific application) and
  event-entry-registraton-uniconbaseapps (career fair entry).

  NOTE (owner, 27 Oct 2026): form-submissions-uniconbaseapps is the GENERAL form
  application for this tenant and the default destination of every form that does
  not name a more specific one. registration-forms-uniconbaseapps does not exist
  and must not be used. Always send cmsObjectType explicitly so the platform
  default is never relied on.

  FOLDER ROUTING (29 Oct 2026): the trial exam registration page is the first
  form that names its folder - it sends
  folder: { name: "2026-11-07-vancouver-cemc-trial-exam-registration" } from the
  form attribute data-gw-form-folder, so every submission of that page lands in
  that folder (created on first use) instead of an invisible folder-less state.
  Add the same attribute to any other form that needs its own folder; leave it
  out to use the app default structure or the platform YYYY-MM fallback.

  OBJECT NAMING (29 Oct 2026): the same page now names the record too - it sends
  nameTemplate: "{{student_name}}" from the form attribute
  data-gw-form-name-template, so each submission shows the student name inside
  that folder instead of a timestamp. Rename an attribute to change the naming:
  data-gw-form-name-template for a template over the answers,
  data-gw-form-object-name for one fixed title (it wins over the template).

  CITY PAGES (29 Oct 2026): the same date is offered as six pages, one per city,
  each with its own folder, label and colour theme:

    formpages/2026-11-07-vancouver-cemc-trial-exam-registration.html   (brand orange)
    formpages/2026-11-07-calgary-cemc-trial-exam-registration.html     (crimson)
    formpages/2026-11-07-edmonton-cemc-trial-exam-registration.html    (emerald)
    formpages/2026-11-07-toronto-cemc-trial-exam-registration.html     (royal blue)
    formpages/2026-11-07-ottawa-cemc-trial-exam-registration.html      (violet)
    formpages/2026-11-07-victoria-cemc-trial-exam-registration.html    (teal)

  The file name, the route, data-gw-form-type and data-gw-form-folder are the
  SAME string on each page, so one submission lands in exactly one city folder.
  Only Vancouver has a confirmed venue; the other five answer "Venue to be
  confirmed", carry no Google Maps link and store venue_city=TBC.
