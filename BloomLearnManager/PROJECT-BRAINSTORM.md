# PART 2: STUDENT STUDY MANAGEMENT SYSTEM (Grade-Level Mentorship Platform)

## 2.1 What This System Is

A platform that takes the **math curriculum content** created by workers and delivers it to **real students** (Grade 5-11) in a structured, mentored study program. Workers become **mentors** who guide students through the curriculum, monitor progress, and ensure mastery before advancing.

## 2.2 Core Design Principles

1. **Content is stable, mentorship is the variable** — The math curriculum is well-defined (Grade 5-11 topics). What we're testing is the mentorship model.
2. **Workers mentor students → supervisors mentor workers** — Two-tier mentorship. Workers learn to mentor (valuable skill!) while being mentored themselves.
3. **Mastery-based progression** — Students don't advance to next topic until current topic is mastered (score ≥ 80% or mentor approval).
4. **The system is a tool, not a replacement** — Mentors make judgment calls. The system facilitates, doesn't automate.

## 2.3 User Roles

| Role | Who | What They Do |
|------|-----|-------------|
| **Student** | Grade 5-11 learners | Receive content, study, complete exercises, submit work, request help |
| **Mentor** | Our 10 workers (students themselves!) | Assign content, review submissions, give feedback, approve progression, hold 1-on-1 sessions |
| **Supervisor** | Program manager (you) | Assign students to mentors, monitor all progress, intervene when needed, mentor the mentors |
| **Content Curator** | Workers + you | Organize curriculum into deliverable units, ensure quality, fill gaps |

## 2.4 Content Structure

```
Grade X
  └─ Unit 1: [Topic Area]
       ├─ Lesson 1.1: [Concept] → Document + Exercises + Assessment
       ├─ Lesson 1.2: [Concept] → Document + Exercises + Assessment
       └─ Unit 1 Review → Comprehensive test
  └─ Unit 2: [Topic Area]
       ├─ Lesson 2.1: ...
       └─ ...
  └─ Final Grade X Exam
```

Each deliverable "packet" contains:
- 📄 **Study Document** (the AI-generated content, quality-reviewed)
- 📝 **Practice Exercises** (5-10 problems with solutions)
- ✅ **Mastery Check** (short quiz, auto-graded or mentor-reviewed)
- 🎯 **Learning Objectives** (what student should be able to do after)

## 2.5 Student Workflow

```
1. Mentor assigns Lesson Packet → Student receives notification
2. Student studies document (self-paced, async)
3. Student completes Practice Exercises
4. Student takes Mastery Check
5. Auto-grade OR mentor reviews submission
6. Score ≥ 80% → ✅ PASS → Next lesson unlocked
   Score < 80% → 🔄 Retry → Mentor provides additional help
7. Repeat until unit complete → Unit Review
8. Unit Review passed → Next unit
9. All units complete → Grade X Final Exam
10. Grade X passed → 🎓 Advance to Grade X+1
```

## 2.6 Mentor Workflow

```
1. See dashboard of assigned students
2. For each student: current lesson, progress %, last activity
3. Student submits mastery check → mentor reviews
4. Mentor can: Approve / Request revision with feedback / Schedule 1-on-1
5. Mentor monitors: is student stuck? Behind schedule? Excelling?
6. Weekly: mentor writes brief progress note for each student
7. Mentor participates in supervisor-led "mentor huddle" (weekly)
```

## 2.7 How Workers Learn Through Mentoring

| Skill Developed | How |
|----------------|-----|
| **Teaching ability** | Explaining math concepts to real students |
| **Feedback skills** | Giving constructive, specific feedback on student work |
| **Content evaluation** | Seeing which content works and which doesn't in practice |
| **Patience & communication** | Working with struggling students, breaking down concepts |
| **Leadership** | Taking responsibility for another person's progress |
| **Data-informed decisions** | Using progress data to decide when to intervene |

## 2.8 The Tool (Future Application)

This system needs its own HTML tool application with:

| Feature | Purpose |
|---------|---------|
| **Student Registry** | Add/manage students with grade level, mentor assignment |
| **Content Library** | Organized by grade → unit → lesson, with all packets |
| **Assignment Board** | Mentor assigns packet → sets due date |
| **Submission Inbox** | Mentor sees pending submissions to review |
| **Progress Dashboard** | Visual progress per student (%, pace, stuck indicators) |
| **Messaging/Notes** | Mentor ↔ Student notes within the system |
| **Grade Advancement** | Auto-suggest when student is ready for next grade |
| **Weekly Reports** | Auto-generated summary for supervisors |
| **Mentor KPIs** | Track mentor response time, approval rate, student progress |

## 2.9 Testing the Mentorship Model with Workers First

**Before rolling out to real students**, use workers as the test cohort:

### Phase A: Workers Mentor Each Other (Week 1-2 of testing)
- Pair workers: one is "mentor," one is "student"
- "Student" studies 3 math topics they're LESS familiar with
- "Mentor" guides them through, reviews work, approves progression
- This validates the system with people who can give detailed feedback
- Each worker experiences BOTH roles

### Phase B: Workers + A Few Real Students (Week 3-4)
- Bring in 2-3 real students (friends, family volunteers, pilot group)
- Each worker mentors 1 student
- Supervisor closely monitors
- Daily debrief: what worked? what didn't? what needs changing?

### Phase C: Full Cohort (Week 5+)
- Scale to 10-20 students
- Workers each mentor 1-2 students
- System is stable, processes are documented
- Workers have mentoring experience and confidence

# PART 3: DRONE PILOT CERTIFICATE — Test Cohort Plan

## 3.1 Why This is a Brilliant Test Case

1. **Curriculum already exists** — You have it prepared
2. **Clear outcome** — A recognized certificate, not just "learning"
3. **Workers are motivated** — Drone piloting is cool and career-relevant
4. **Tests the mentorship model** — Workers study → get mentored → earn certificate → become mentors for next cohort
5. **Creates a template** — If this works, the same system applies to AI certificates, coding bootcamps, etc.

## 3.2 Drone Pilot Certificate — Cohort Plan

### Timeline (within the 2-month program)

| Week | Activity | Notes |
|------|----------|-------|
| **Week 1** | Orientation + Theory Module 1: Regulations & Safety | Self-study + group discussion |
| **Week 2** | Theory Module 2: Flight Principles & Weather | + Practice quiz |
| **Week 3** | Theory Module 3: Navigation & Operations | + Mid-point assessment |
| **Week 4** | Theory Module 4: Emergency Procedures & Ethics | + Final theory exam |
| **Week 5** | Practical: Simulator training | Using drone flight simulators |
| **Week 6** | Practical: Basic flight maneuvers | Real drones, supervised |
| **Week 7** | Practical: Mission planning & execution | Complex scenarios |
| **Week 8** | Final practical exam + Certificate awarded 🎉 | Celebration! |

### Mentorship Structure for Drone Cohort

| Role | Person | Responsibility |
|------|--------|---------------|
| **Drone Instructor** | You or external expert | Teach practical sessions, assess flight skills |
| **Theory Mentor** | Supervisor / experienced worker | Guide through modules, check understanding |
| **Peer Study Groups** | Workers in pairs | Discuss concepts, quiz each other |
| **Progress Monitor** | The Bloom & Learn tool | Track module completion, exam scores |

### Certificate Structure

The certificate should include:
- 📜 Completion of theory modules (4 modules)
- 🛩️ Practical flight hours logged (minimum X hours)
- ✅ Flight skills assessment (checklist of maneuvers)
- 🎓 Final certificate (printable, verifiable)

### How This Tests the Mentorship Model

| What We Test | How |
|-------------|-----|
| **Content delivery** | Are the drone modules clear and self-study-able? |
| **Progress tracking** | Can mentors see who's falling behind? |
| **Assessment workflow** | Are theory exams auto-graded? Is practical assessment consistent? |
| **Mentor intervention** | When a worker struggles, does mentor notice and help? |
| **Completion rate** | Do all 10 workers finish? If not, why? |
| **Worker satisfaction** | Do they feel supported? Is the workload manageable? |

### Data to Collect

- Time spent per module
- Quiz/exam scores per attempt
- Flight hours logged
- Mentor interaction count
- Worker feedback (weekly survey: 1-5 on clarity, support, difficulty)
- Completion rate & time-to-completion
