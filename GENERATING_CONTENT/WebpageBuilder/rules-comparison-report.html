🟢 What we GAINED (new capabilities in v2.0)

1. window.gw SDK v2 — the only integration surface

A single documented API for everything: routing (gw.navigate, gw.getPageParams), auth (gw.getUser, gw.login/logout), storage (gw.storage), formatting (gw.formatCurrency/formatDate), toasts (gw.notify), modal (gw.showModal), sanitize (gw.sanitize), analytics (gw.track).

2. Data reads with filters & live updates

gw.db.query/get/subscribe — filters (==, !=, >, >=, <, <=, in, contains), relations, facets, pagination (≤200), language scoping, and SSE live updates with a polling fallback. Public types only.

3. Operations engine — structured, transactional writes

gw.db.operation with server-side validation, safe formula DSL, role/owner permission checks, multi-target transactional writes, idempotency keys and email/contextFunction hooks. The page only references operations; it can never define them.

4. Flows — real multi-step processes

Checkout, booking, registration as server-authoring configs: steps with dataDefinitions, validation rules, amountFormula, payment steps and done-step hooks. Flow state is server-side (httpOnly cookie) — the client cannot forge steps.

5. Cart API

Server-computed totals, anonymous cart cookie identity, gw:cart-changed events, add/update/remove/clear actions. Money is never calculated client-side.

6. Built-in widget islands

9 ready-made components via <div data-gw-app>: menu, cart, checkout-flow, slot-picker, seat-map, account-dashboard, rewards, order-status, search-box — plus custom islands with gw.apps.register.

7. First-class SEO output

A dedicated === SEO === section: metaTitle/Desc/Robots, OpenGraph, Twitter cards, canonical, sitemap priority/frequency and schemaItems JSON-LD (WebPage, Product, FAQPage, Event…).

8. PAGE META output

=== PAGE META === carries name, slug, language, publish status, requireAuth (auto login redirect) and templateContentType. Drafts are hidden without a preview secret.

9. SPA navigation & router

data-ic-nav-href deep links with plain href fallback, gw.navigate(), per-page CSS dedup/unmount, and an explicit idempotent script lifecycle on every navigation.

10. Theme integration

Site theme colors exposed as --gw-color-* CSS variables; gw.formatCurrency uses the site's currency config. Brand colors no longer need hard-coding.

11. Codified security guardrails

Honeypot fields (gw_hp/website/company), 2-second anti-bot timing, origin checks, rate limits, reCAPTCHA option, data-gw-config JSON validity, no document.write/top-level await.

12. Explicit lifecycle contract

Precise rules for how code runs: body fragment injection, CSS appended to <head>, JS via Blob URL after double rAF, island auto-mount, gw:content-ready event, script-error isolation.

13. CMS CONFIG NEEDED escape hatch

When an operation/flow the page needs doesn't exist, the generator says so explicitly instead of inventing writes — clear handoff from AI to CMS author.

🔴 What we LOST (retired in v2.0)

1. The block system

sp_contents.blocks[], block types (html, html-code, text, image, json, faq-item), cssClassNames, settingsJSON and fullWidthBlockCss are gone. Content now lives ONLY in data.htmlPage.code.{html,css,js}.

2. Nunjucks templating

Server-side template evaluation of page content is removed. {% raw %} wrapping, block variables and Nunjucks-aware escaping are no longer needed or supported.

3. Block-level data widgets

object-query-list (read), dynamic-form (write) and JSON renderer blocks are replaced by the gw.db API, the data-gw-form protocol and island widgets.

4. gw- class naming convention

The mandatory gw- prefix is replaced by a unique page-class scoping rule (.shop-home) — because CSS is injected globally and removed on unmount.

5. window.MyPage namespace convention

No longer required (top-level function declarations are auto-hoisted to window by the platform). Replaced by the stronger idempotency contract.

6. GW-PAGE-ID traceability comment

The GW-PAGE-ID/GW-PARTIAL-ID declaration comment convention is gone (version stamps in the tool cover traceability instead).

7. Embedded style/script as the primary mechanism

In-content <style>/<script> blocks are only tolerated now — the canonical split is code.css/code.js.

8. Anything-goes JS writes

Direct database/REST/API writes from page code are explicitly forbidden. Every write must be an operation, a flow, a form submit or a cart call.

⚖️ Should we bring them back? (short verdicts)

Lost featureVerdictOne-line reason / replacement
1. Block system NO HTML fragment does it all. If editors need reusable pieces → add small data.sections composition, not blocks.
2. Nunjucks NO It was a security risk. Template pages (data.templateContentType) already give the "one template → many object pages" flow.
3. Block data widgets PARTLY Forms already covered by data-gw-form. Add only a generic no-code list widget.
4. gw- class prefix PARTLY No mandatory prefix. Optional: shared site CSS + reserve gw- for shell components.
5. window.MyPage namespace SMALL YES Hoisted functions can collide. Add a per-page gw.ns object (tiny change).
6. GW-PAGE-ID comment YES Auto-inject a page/slug comment — zero author effort, great for support/debug.
7. Embedded style/script as primary NO The code.css/js split is better. Optional: legacy import/normalizer to migrate old pages.
8. Anything-goes JS writes NEVER Removed for security. Operations/flows/forms/cart replace it.

Bottom line: 4 of 8 need nothing; 3 are optional small additions; only 1 (auto page comment) is a clear cheap win. Nothing needs the old mechanisms back as they were.

🔵 What we STILL HAVE (kept across both versions)

1. Body-fragment model

No <html>/<head>/<body>/<!DOCTYPE> — the page is injected between a platform-rendered header and footer (never generate your own chrome).

2. SEO & accessibility baseline

Exactly one <h1>, logical heading hierarchy, semantic landmarks, alt text, labels on inputs, visible focus and contrast.

3. Image discipline

Alt + width + height on every <img>, lazy loading below the fold, CLS avoidance. (External absolute URLs are now officially fine.)

4. Mobile-first responsive

Mandatory @media queries, 48px tap targets and prefers-reduced-motion support.

5. Vanilla JS only

No jQuery/Bootstrap/Tailwind, no CDN scripts, no frameworks — plain JavaScript, now with explicit idempotency rules.

6. Security hygiene

No secrets in code; user/data content rendered via textContent (now also gw.sanitize); XSS escaping required.

7. Size budgets

HTML < 100 KB, CSS < 50 KB, JS < 200 KB — unchanged.

8. Multi-language pages

Language from meta.language; sibling pages share a contentId; platform handles hreflang and the language switcher.

9. Site-wide header/footer objects

default-header/default-footer (and default-settings) remain reserved slugs rendered by the platform.

10. SEO length guidance

~60-char titles, ~155-char descriptions, sitemap feeds — now generated from the === SEO === section.

11. IIFE + scope hygiene

Scripts wrapped in IIFEs; global collisions avoided — now with loop-closure warnings (let/const per iteration).

12. Forms

Still available, evolved from dynamic-form blocks to the data-gw-form protocol with honeypots and status elements.

13. Stripe payments

Still supported, evolved from block config to flow payment steps and payment intents (pi_stub_* in pilots).

14. File uploads

Still supported via multipart form submissions (≤10 MB server limit).

15. Emails

Still supported, evolved from AWS SES block config to operation/flow hooks (email hook type).

16. Routing & deep links

Still present, evolved to the SPA router (data-ic-nav-href, gw.navigate) with plain-href SEO fallback.

17. Read-only public data access

Still available, evolved from object-query-list blocks to gw.db.query/get/subscribe with public-type access limits.

⚙️ What this means for the WebpageBuilder tool (already implemented in build 2026-08-18a)

  • Prompts, output contract and minimal/step prompts now demand the === HTML/CSS/JS/SEO/PAGE META === layout plus === CMS CONFIG NEEDED ===.
  • The parser captures SEO and PAGE META JSON (lenient parsing for trailing commas/comments) and stores them in the saved value.
  • The compliance engine ("Page Quality Checker") now enforces v2.0 guardrails: body-fragment-only, scoped CSS, idempotent JS, data-gw-form protocol, valid data-gw-config JSON, reserved honeypot names, no document.write.
  • The preview and the downloaded standalone page inject a minimal window.gw mock so gw-based pages run outside the platform.
  • Exports changed: Copy Page Object JSON (data.htmlPage.code + seo + page meta) and Copy Generator Output (raw === sections). The old GW html-code block export is gone.
  • Page-type playbooks now recommend the right widget islands, flows and operations per page type.
