Where do the documents go - option b vs option c

website-builder-uniconbaseapps folders - prepared for the HtmlToolLibraryItem decision - date: 2026-09-23

The taxonomy from folder-hierarchy-import.json is imported into the CMS ONCE (about 220 folders: Business > General > category > leaf subcategory). Tool records already sit in their leaf folders. The question is only: where do each tool's 5 documents (webpage, help, updates, presentation, social) live inside the website-builder app?

Option b - a second copy of the treeCOPY

The website-builder app gets its OWN copy of the full hierarchy under a root folder like "html-tool related pages". Each copied leaf holds the 5 documents of every tool in that leaf.
  • Tool Library tree (imported)
    • Personal > Personal Finance
      • Tax Preparation (leaf)
        • PersonalTaxPreparation recordhtml-tool-library object
  • Website-builder app - "tool pages" root (copy)
    • Personal > Personal Finance (copy)
      • Tax Preparation (leaf copy)
        • webpage object
        • help object
        • updates object
        • presentation object
        • social object
Cost: the hierarchy exists twice - about 220 extra folders to import and keep in sync forever. Gain: all documents sit in a separate tree, apart from the tool records.

Option c - the SAME tree, sharedSHARED

No copy at all. Every folder node in the import file already carries a categories list - we add website-builder-uniconbaseapps to it once, re-import, and the same folders serve both apps. Documents are created in the leaf where the tool record already lives.
  • The ONE taxonomy tree (imported, shared)
    • Personal > Personal Finance
      • Tax Preparation (leaf)
        • PersonalTaxPreparation recordhtml-tool-library object
        • webpage object
        • help object
        • updates object
        • presentation object
        • social object
        • version objects (v1..v20)website-builder objects
Cost: one edit to the import file (add the app to each folder's categories), re-import. Gain: one filing system, zero duplication - everything about a category lives in its leaf.

Recommendation: option c. The import file was built with a categories array on every folder exactly so several applications can share one hierarchy. Option b gives slightly easier per-type browsing on the website, but that can be reproduced with a slug filter - and it costs a permanent double hierarchy. HtmlToolLibraryItem already implements c: it creates every document and version snapshot in the leaf folder of its own record.
