Desktop Code Development Tool

Feasibility analysis - can Electron plus plain JavaScript cover the requested feature set? Companion analysis for code-devtool-ssot.html (the governing document).

Verdict: YES. Every requested capability - AI chat, an AI agent that edits a selected folder like VS Code with Copilot, feature management, and a live web preview - is achievable with Electron and JavaScript only. No TypeScript, no UI framework, and no native module builds are required for version 1. Three honest caveats are listed at the end.

1. The request

  1. Desktop code development tool.
  2. AI chat feature.
  3. Develops code in a user-selected folder, the VS Code workflow.
  4. AI agent capability with GitHub Copilot-like capabilities.
  5. Feature management through an SSOT document (the template).
  6. Live preview of the web UI inside the tool; web development only: HTML/CSS/JS projects (like this repository) or Next.js projects, nothing else.
  7. Electron and JavaScript only.

3. Architecture in one view

Main process (Node.js)folder access, project file service, preview server, Next.js runner, terminal service, agent runtime, AI provider clients
Preload bridgecontextBridge allowlist - the ONLY path between UI and Node.js power
Renderer (Chromium)plain HTML/CSS/JS UI: explorer, editor tabs, chat, terminal, preview; zero Node.js access
  • Security baseline from day one: contextIsolation on, nodeIntegration off, sandbox on, allowlisted IPC channels, content security policy, secrets in safeStorage.
  • Core invariant (ROOT-ONLY): no file outside the opened project folder can ever be read or written by the tool, the agent, or an agent command. One service resolves every path.
  • Everything is plain JavaScript files - .js, .html, .css - no build step for our own code.

5. AI provider facts

  • GitHub Copilot API (api.githubcopilot.com) is the primary provider: OpenAI-compatible chat completions with streaming, authenticated with an OAuth device flow or a personal access token, and it requires a GitHub account with a Copilot subscription.
  • To verify at implementation time (tasks T-07 and T-18 in the SSOT): exact endpoints, available models, rate limits, and whether an inline completion endpoint exists. The provider abstraction means any OpenAI-compatible endpoint can replace it without touching the UI.
  • Fallbacks are already designed in: any OpenAI-compatible API, and later a local model (idea I-03).

7. Constraints and non-goals

  • JavaScript only: no TypeScript, no UI framework, no native module builds in version 1 (the terminal is a command session, not a PTY).
  • Web projects only: static HTML/CSS/JS and Next.js. Anything else is refused with a clear message, never attempted.
  • No cloud backend: state lives in local JSON files; the only traffic out is the AI API call.
  • Not a VS Code clone: no extension marketplace, no language servers - the tool does one job well.

8. Answer to the question

Yes, we can do this with Electron and JavaScript only. The plan is fully specified in code-devtool-ssot.html - decisions CODE-01 to CODE-09, 21 tasks in 8 release groups, 7 logged risks, and a publish gate. Three honest caveats:

Caveat 1. Inline completion ships only after verifying that the Copilot API exposes a completion endpoint; otherwise it is deferred (SSOT task T-18, limitation L-02). Chat and agent capabilities do not depend on it.
Caveat 2. The v1 terminal is a command session, not a full interactive PTY (no vim-style programs) because native modules are excluded; node-pty can be added later as a new decision.
Caveat 3. "All Copilot capabilities" means the practical set in section 4, not the VS Code extension ecosystem - that part is intentionally out of scope for a single-purpose tool.
