0. WHAT WE ALREADY KNOW (verified, no answer needed)

Reads work today against the Public API v2 with an API key header:

    GET  {base}/api/v2/objects/{cmsObjectType}          list
    GET  {base}/api/v2/objects/{cmsObjectType}/{id}     one object
    header: x-api-key: <key>
    host:   applicationstore.uniconhub.com

Field values live in productData.data_categoriesBased.

The HTML Tool Item Editor (UNICON-TOOLS/HtmlToolLibraryItem) already writes
tool records and documents, but only from inside the CMS, through the relay:

    tool.requestObjects('query' | 'get' | 'create' | 'update' | 'delete', {...})

It creates a document with:
    { mainObjectType, name, productData: { data_categoriesBased: payload }, typeId }
and updates one with:
    { mainObjectType, objectId, productData: { data_categoriesBased: payload } }

Document targets it uses:
    webpage / help / updates / presentation -> website-builder-uniconbaseapps
        field webpageContentWithBuilder: { code: { html, css, js }, seo, pageMeta, version }
        folder typeId: www.uniconhub.com   (help uses help.uniconhub.com)
    social  -> tool-social-content-uniconbaseapps
        fields name, slug, contentHtml   (no folder; application default)
    versions -> tool-code-versions-uniconbaseapps

Our engine runs in Node on the operator's machine (no CMS session), so it
needs the equivalent of requestObjects over HTTP.

Q-04 (factory). THE WRITE ENDPOINTS  --  ANSWERED 2026-11-18
Answered by the v2 integration document, not by this sheet. Summary:

    POST  /api/v2/objects/{cmsObjectType}                  create  -> 201
    GET   /api/v2/objects/{cmsObjectType}/{objectId}       read
    PATCH /api/v2/objects/{cmsObjectType}/{objectId}       merge update
    PUT   /api/v2/objects/{cmsObjectType}/{objectId}       replace content
    POST  /api/v2/objects/{cmsObjectType}/query            query
    POST  /api/v2/objects/{cmsObjectType}/bulk             500 ops, no deletes
    GET   /health

Same host for reads and writes, base https://<tenant-host>/api/v2.
PATCH and PUT are compare-and-swap on version through If-Match; a missing
base is 409 CAS_CONFLICT and never writes. Deletes are not available.
Full detail: docs/STORE-API-V2.md sections 3, 5 and 6.
