2. THE SPECIFICATION (as supplied by the owner)
-----------------------------------------------

ROLE
Build a complete, production-quality CMS html-tool called "Asset Drive".

PURPOSE
An in-CMS media/asset manager that behaves like the existing Asset Drive (FolderManager):
it browses virtual folders built from file paths, previews images, copies asset URLs,
downloads whole folders, and allows uploads and basic file management.
The tool stores its own data in its CMS field value. It does NOT use Firestore directly.

DELIVERY FORMAT
Return exactly three code blocks, labeled and ordered. No explanation outside them.

[HTML]
body markup only - no <html>, <head>, <body>, <style>, <script> wrapper tags.
External CDN <script> tags ARE allowed here (use them only for JSZip).

[CSS]
stylesheet rules only - no <style> wrapper.

[JS]
JavaScript only - no <script> wrapper. Must begin with tool.onReady(...).

PLATFORM RULES - MANDATORY
- The tool runs in a sandboxed iframe. No localStorage, no sessionStorage, no cookies.
- No direct fetch() to external URLs. Use only the tool.* SDK channels below.
- No alert(), confirm(), or prompt(). Build in-tool modals instead.
- No raw postMessage. Use only the tool.* SDK.
- Never use DOMContentLoaded or window.onload. tool.onReady is the single entry point.
- Values may be any JSON type. Persist with tool.setValue.
- Escape all user-generated strings when rendering. Never inject file names with innerHTML.
- Always call tool.declareParams and tool.reportMissingParams inside tool.onReady.
- Always check tool.isReadOnly() on first load and on change; lock editing when read-only.
- Call tool.resize() after layout changes that affect iframe height.
- The tool must be fully functional with no placeholders and no TODO comments.

SDK CHANNELS - USE THESE
- tool.getValue() / tool.setValue(value) - load and persist this field's value.
- tool.onValueChange(cb) - re-render when the value changes externally.
- tool.isReadOnly() / tool.onReadonlyChange(cb) - read-only handling.
- tool.getUser() - roles and effectiveAccess for soft UI gating.
- tool.param(name, default) - admin parameters.
- tool.notify(message, 'success' | 'info' | 'warning' | 'error') - CMS toasts.
- tool.openUrl(url) - open a file in a new tab (use for "Open in new tab" and one-by-one downloads).
- tool.requestUpload(accept, cb) - host file picker upload. cb(error, file) where file = { name, url, size, type }.
  Requires allowUpload. Handle errors gracefully when unavailable.
- tool.requestFetch(url, { timeoutMs, maxBytes }, cb) - server-side fetch relay for binary files.
  GET only, https only, host allowlist, hard cap 500 KB, returns { status, contentType, dataUrl } for binary
  and { status, contentType, text } for text. Use this ONLY for ZIP packing. Handle errors and skips.
- tool.requestSave(cb) - optional explicit save, only if a save button is used.
- tool.getParentPageUrl() - origin + pathname of the CMS page (display/share only).
- tool.declareOutput(schema) - declare the saved value shape.
- tool.declareParams([...]) - declare every param the tool reads.

DATA MODEL - FIELD VALUE
value = {
  folderId: string,
  name: string,                    // drive title, default "Asset Drive"
  files: FileRecord[]
}

FileRecord = {
  id: string,                      // stable unique id
  name: string,                    // storage file name
  displayName?: string,            // user-visible name, falls back to name
  path: string,                    // "folder/subfolder/file.png" - never leading slash
  url: string,                     // public download URL
  thumb_url?: string,              // optional thumbnail URL
  cdnUrl?: string,                 // optional CDN override - effective URL wins
  contentType?: string,
  size?: number,
  updatedAt?: number,              // epoch ms
  firstUploadedAt?: number,
  starred?: boolean,
  locked?: boolean,
  tags?: string[],
  colorLabel?: 'red' | 'orange' | 'yellow' | 'green' | 'blue' | 'purple',
  versions?: [{ url, size, updatedAt }]   // max 3 old versions on overwrite
}

Effective URL rule (use everywhere): file.cdnUrl || file.url
Thumbnail rule: file.thumb_url || file.cdnUrl || file.url
Image detection: contentType starts with "image/" OR extension in
png, jpg, jpeg, gif, webp, svg, bmp, ico, avif, tiff.

TOOL PARAMETERS - DECLARE ALL

- maxUploadSizeMb (number, default "25")                - reject larger uploads with a toast

Call tool.reportMissingParams for any param that is truly required (none should be).

SEARCH, FILTER, SORT

   Each row shows a file count and is disabled when empty.
2. Bulk bar: Download ZIP for selected files.
3. Folder context menu: Download folder (ZIP), recursive.

ZIP IMPLEMENTATION DETAILS
- Load JSZip from the CDN <script> tag. If JSZip is missing, show an error and keep
  the one-by-one option available.
- Process files sequentially:
  a. Set button text to "Packing 3/12...".
  b. Call tool.requestFetch(effectiveUrl, { timeoutMs: 15000, maxBytes: 500000 }, cb).
  c. On success with dataUrl: strip the "data:*;base64," prefix, decode base64 to Uint8Array,
     and add it to the archive.
  d. Skip failures and files exceeding the 500 KB relay cap, but keep counting them.
- Sanitize every ZIP path segment: replace \ / : * ? " < > | with "-", trim spaces,
  collapse whitespace. Keep folder structure after sanitizing.
- Guarantee unique entry paths: append " (2)", " (3)" before the extension on collision.
- Generate with compression "STORE" (images are already compressed).
- Trigger the download with URL.createObjectURL plus a temporary <a download> element,
  then revoke the object URL.
- Archive name: current folder name, or the drive name at root, sanitized, plus ".zip".
- When stripping the current folder from entry paths, files sit at the ZIP root.
- Progress states: "Preparing N files...", "Packing i/N...", "Creating ZIP...".
- Final feedback: "Zipped 12 files" or "Zipped 10 of 12 files" (skipped count implied).
- Because the relay rejects files over 500 KB, explain in the UI hint:
  "Large files are skipped in ZIP mode; use Download files one by one."

ONE-BY-ONE DOWNLOAD DETAILS
- For each file call tool.openUrl(file.cdnUrl || file.url) with a 300-400 ms delay.
- Show progress "Downloading 3/12..." in the Download button.
- Warn in the row tooltip: "Your browser may ask you to allow multiple downloads."
- Count started downloads and notify: "Started 10 downloads" or "Download failed".

UPLOAD AND FILE OPERATIONS
- Upload button calls tool.requestUpload(accept, cb) into the current folder.
  Build a FileRecord:
  id = unique id, name = returned file.name, path = currentPath + "/" + name (no leading slash),
  url = returned file.url, contentType = returned type, size = returned size,
  updatedAt = Date.now(), firstUploadedAt = Date.now().
- If a record with the same path exists, treat it as overwrite:
  push the old { url, size, updatedAt } into versions (max 3 old entries),
  keep the record id, firstUploadedAt, starred, locked, tags, colorLabel, cdnUrl,
  replace url/size/updatedAt with the new upload.
- If the new name closely matches an existing different path (normalized lowercase,
  non-alphanumerics removed), show a non-blocking duplicate warning banner with Dismiss.
- Reject files larger than maxUploadSizeMb with a toast.
- New Folder: in-tool modal with a single text input, creates nothing physical -
  creates/ensures the path exists by being selected; show it in the tree immediately.
  (Implementation: store created empty folders in value.emptyFolders: string[] so
  empty folders survive reloads. Include emptyFolders in the data model.)
- Rename file: edits displayName only; path, URL and storage path never change.
- Move: modal lists Root and every folder path; moving rewrites file.path to the new
  folder + file name. Show a warning that the stored URL remains unchanged.
- Duplicate: copy the record with a new id and a name ending in " (copy)".
- Delete file: confirmation modal, removes the record. Warn if firstUploadedAt exists:
  "Deleting will remove this record; the stored URL becomes unmanaged."
- Delete folder: confirmation modal listing the number of files, removes all records
  whose path equals the folder or starts with "folder/".
- Locked files cannot be deleted or moved until unlocked.
- Star, Unstar, Color label (none, red, orange, yellow, green, blue, purple), Tags editor.
- All mutations update local state immediately and call tool.setValue(newValue).
  If showSaveButton is on, the Save button calls tool.requestSave and toasts the result.

3. BUILD-TIME CONFLICTS TO RESOLVE (from html-tool-rules.txt)
-------------------------------------------------------------
1. JSZIP AND THE NO-EXTERNAL-RESOURCES RULE
   The specification allows an external CDN <script src> tag for JSZip and a
   jszipCdnUrl parameter. html-tool-rules.txt forbids external resources in the
   three files (a stalled CDN script freezes the whole tool in the CMS sandbox).
   Resolve before coding: ship a small built-in STORE-only ZIP writer inside the
   JS block (the archive uses compression "STORE", so a writer is about 60 lines
   plus CRC32), or load a library through the parent relay. Do not put a CDN
   script tag in the HTML block without an explicit owner decision.
2. INLINE-SCRIPT TOKENIZER SAFETY
   No raw </script and no unclosed <!-- anywhere in the JS block (write <\/script
   and \u003C!--). This has killed tools in the CMS before.
3. BUILD BADGE
   Carry TOOL_BUILD (YYYY-MM-DD-rN) in the JS block, show it in the header, log it
   on boot, and put the per-file build stamp as the first line of each file.
4. DATA SHAPE
   Add emptyFolders: string[] to the declared output schema, not only to the text
   model, so the saved shape is explicit.
