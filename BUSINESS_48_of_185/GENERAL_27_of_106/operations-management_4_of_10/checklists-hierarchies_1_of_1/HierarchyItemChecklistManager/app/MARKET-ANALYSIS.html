1What the tool actually is

Under the hood, the tool is a template-matrix program tracker. The engine is entirely general-purpose: an arbitrary-depth hierarchy of items, where the items that sit at the bottom of the tree are tracked against one shared checklist template, and everything is watched from a single grid. Only the content layer - the names Section / Sub-section / Lesson / Task, the icons, and the default template (Lesson plan, Worksheet, Quiz, Answer key) - is curriculum-specific.

Core engine capabilities

  • A hierarchy where every level is an item: folders (sections, sub-sections) contain units, units contain the actual work items
  • A configurable standard task template applied to every unit - each new unit automatically gets the same set of child items
  • The matrix view: one row per unit, one column per template step, each cell a clickable status square
  • Status cycles on cells with one click (To do / In progress / In review / Done / Blocked)
  • Derived statuses: folders and units inherit their status from their children - no manual parent updates ever
  • Rollup completion percentages at every level, plus a dashboard ring and counts
  • Assignees pulled from the CMS permitted-users list, assignable per item or per branch
  • Due dates, overdue warnings, filters, undo, CSV and printable PDF reports
  • Team performance table (admin-only) and per-section progress bars

What it is not

  • Not a project manager: no Gantt charts, dependencies, sprints or resource planning
  • Not a recurring-obligation tracker: it tracks the delivery of one program, not a repeating calendar of duties (that is the RecurringTaskManager pattern)
  • Not a kanban board: columns are template steps, not workflow lanes, and items are fixed to their unit
  • Not an evidence/audit system: items carry notes and completion stamps, but no per-item conversation thread or history log
The defining feature: one template, applied to a hundred units, watched from one grid. Create a unit and its checklist appears; click a cell and the whole branch re-computes its progress automatically.

2Today's user: the curriculum builder

The current instance serves an education team building a curriculum. Its content maps the shape of course production: sections organize the program, sub-sections group related lessons, and every lesson is delivered against the same four-step template - Lesson plan, Worksheet, Quiz, Answer key. The grid shows every lesson of every section at once, colored by status, and the outline gives the tree view for daily work.

That user is the first beachhead, but it is only one instance of a much larger pattern: any program where many similar units must each complete the same small set of steps, and one person needs the whole picture on a single screen.

5Customer types and how it could be sold

  • End-user subscriptions (B2B): L&D departments, e-learning studios, franchise operators and HR teams pay per workspace. They buy outcomes: nothing falls through the cracks, the whole program is visible, reports are one click.
  • Vertical editions: the same engine, re-skinned and re-seeded - CourseOps edition, Franchise Rollout edition, Onboarding edition, Audit Readiness edition. Each edition is mainly a different default template and terminology.
  • Agencies and consultancies (B2B2B): L&D agencies, content studios and implementation consultants run one instance per client program and watch all clients from the dashboard.
  • Platform-embedded (B2B2C): inside UniconHub it sells as one CMS tool among many - "the program matrix" layer next to RecurringTaskManager (recurring obligations), PaymentsManagement and the finance tools. Together they cover obligation-plus-delivery.
  • Public sector and nonprofits: grant-funded programs and accreditation bodies need per-program checklists with rollup evidence and team visibility - a natural niche.
Prerequisite for every path above: the terminology must become configurable - "Section / Sub-section / Lesson / Task" blocks every non-education buyer. The template (standard tasks) is already editable, which is the biggest lever; naming, icons and a neutral product name are the remaining content-layer changes. The engine needs no changes.

6Similar tools on the market

Yes - but nothing combines its four strengths (template-per-unit, one-screen matrix, derived statuses, per-item assignees with rollup reporting) in one lightweight package. Competitors cluster into four groups:

Group A - General task managers

Todoist, TickTick, Microsoft To Do, Asana, Trello, Notion. All can model lists and boards. Weaknesses for this use case: no native "every unit gets this template" pattern, no unit × step matrix view, no derived parent statuses, and team rollups need configuration. They are also project-shaped, which is the wrong mental model for a program of similar units.

Group B - Spreadsheets (the real incumbent)

Excel and Google Sheets status grids. This is what most target users run today: rows are units, columns are steps, cells are colored. Weaknesses: no derived statuses or rollups without formulas someone must maintain, no per-cell assignees tied to identity, no click-to-cycle (manual editing), no CMS permissions, no one-click reports. The tool must beat the spreadsheet by being easier than maintaining the spreadsheet.

Group C - Checklist and process tools

Process Street, Trainual, Manifestly. They run checklists and SOPs - conceptually close, because a template repeated per run is their core. Weaknesses: they are run-shaped (start a run, complete it sequentially), not matrix-shaped; there is no many-units-at-once grid, no hierarchy rollups, and they carry process documentation weight this tool deliberately avoids.

Group D - Vertical, industry-locked tools (the closest competitors)

7Positioning: the gap this tool fills

The gap

  • Task managers are built for one-off projects, not programs of identical units
  • Spreadsheets hold the matrix but none of the intelligence - no derived statuses, no identity, no rollups
  • Checklist tools run one instance at a time and hide the whole-program view
  • Vertical tools nail one industry but lock you into it

The position

"The program matrix": template your steps once, roll them out to every unit, watch the whole program from one grid, and drill into any unit - with progress that computes itself.

One-line pitches per audience: "every course in your catalog, four steps, one screen" (L&D), "every store, the same checklist, one grid" (franchise), "every new hire, every step, tracked" (HR), "every audit area, one status board" (compliance).

8Why people will not use it - objections and fixes

Honest negative assessment. Every objection below is a real adoption blocker, ranked by how likely it is to stop someone from using the tool, with the fix that addresses it.

Severity Objection Why it blocks adoption What to do about it
High "The labels say Section / Lesson - that is not my world" A store manager or HR lead sees education vocabulary and concludes the tool is not for them, regardless of the engine. Make terminology and icons configurable (field settings): Section/Sub-section/Lesson/Task become Store/Region/Checklist/Step or Program/Track/Course/Item. This is the single biggest unlock.
High "A spreadsheet already does this" For one person with 30 rows, a colored spreadsheet feels familiar and free. Lead with what the sheet cannot do: derived statuses and rollups without formulas, per-cell assignees from real CMS users, one-click status cycling, team reports. Demo the "100 units, 4 steps" grid.
High "My work is not 100 similar units" Unique, one-off or dependency-driven work gets little value and will be abandoned. Do not sell to project teams. Target unit-heavy programs only (segments scored 7-9 in section 3) and show the ad-hoc "other tasks" column in demos.
Medium "We already use Asana / Notion / Airtable" Teams will not run two overlapping tools. Position as complementary: "your project tool plans the project; this tool runs the program's unit checklist". Offer CSV import as the migration bridge.
Medium "Only one template for the whole program" A mixed program (courses plus compliance items, different steps each) does not fit one global template. Add per-section standard-task templates - columns change per section in the grid. This is the second biggest capability unlock and a natural roadmap item.
Medium "No per-item history or conversation" Notes and completion stamps exist, but there is no dated activity log or chat per item - weaker for audit-style buyers. Position as a delivery tracker, not an evidence system (evidence is the RecurringTaskManager pattern). Add a lightweight change log later: who set which status when.
Medium "Setting up 100 units takes too long" Creating every lesson or store by hand is real onboarding effort. Definition packs per vertical (a ready-made tree plus template, imported in one step), plus the existing multi-add, nested quick-entry and duplicate features.
Medium "It does not handle recurring work" Obligations that repeat every week or month belong elsewhere. Pair with RecurringTaskManager: obligations run there, delivery programs run here. Sell them as a set inside the CMS.
Low "The grid is cramped on a phone" Matrix views are desktop-first; heavy mobile users will struggle. The outline already wraps responsively and the grid scrolls horizontally. Keep mobile as a monitoring view, desktop as the working view.
Low "Too simple for a serious program" Buyers may assume missing depth because the UI is intentionally minimal. That is the position, not a defect: one template, one grid, no project ceremony. Show the reports and team view as the depth.

9Recommendation

  1. Keep the engine, make the vocabulary configurable. Editable labels and icons for Section / Sub-section / Lesson / Task, plus a neutral product name (for example ProgramMatrix or UnitTracker). This alone opens every non-education segment.
  2. Add per-section templates. The grid already renders columns from the standard-task list; letting each section define its own list turns one matrix into a real multi-program dashboard.
  3. Pick two beachhead segments. The strongest matches are e-learning production and corporate L&D (the current user's world, slightly widened), then franchise/multi-site rollout and HR onboarding.
  4. Ship definition packs. One import per vertical that pre-loads the template, a sample tree and terminology - the same playbook as RecurringTaskManager's DEFINITION-PACKS folder.
  5. Sell the matrix screenshot. The pitch is one image: a hundred units, four steps, every cell colored, progress computed. Marketing should lead with that grid, not with features.
  6. Treat the current curriculum instance as reference customer number one and produce a before-and-after case study from it.
