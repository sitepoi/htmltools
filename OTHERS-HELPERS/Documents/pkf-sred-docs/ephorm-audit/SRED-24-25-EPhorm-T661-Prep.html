Line 242 - What scientific or technological uncertainty did you attempt to overcome?

counting...

At the start of the fiscal year, Ephorm Audit was an existing engagement platform, and audit teams still relied on manual review and generic file sharing to organize evidence requests and validate documents. The available tools could store and share files, but none of them could tell whether an uploaded document actually matched the request it belonged to, or classify audit evidence into system-defined categories without human review.

The main uncertainty was whether prompt-based AI could make these judgments reliably. Audit files arrive with inconsistent terminology, different structures, and several schedules inside one document, so we could not tell in advance whether AI could separate related from unrelated files without an unacceptable rate of wrong classifications, or produce useful summaries of requests and chat activity.

Secure file handling at scale raised its own questions. We needed to know whether uploaded files could be validated by content hashing, checked for duplicate names, and moved through template libraries without corrupting downloads or losing request files when several users uploaded at once.

Permissions were another open question. Engagements are shared by auditors, firm managers, assistants, and clients at the same time, and it was unclear whether a single model of engagement-level and request-level roles, including readonly access, could keep every view consistent without allowing actions the role should block.

Dates and timezones added a last uncertainty. Date formats differed between browsers and saved values, and it was unclear whether engagement dates and overdue statistics would stay consistent for users in different timezones.

Line 244 - What work did you perform to overcome the uncertainty?

counting...

The AI validation work happened as a series of prompt and tagging revisions driven by real failures. Early runs produced wrong classifications and attached unrelated files to requests, so we reworked the prompt logic and introduced system tags with descriptions. The AI was then asked to judge each file against request requirements with verdicts of related, unrelated, or partial, every system tag was sent to the AI for a relatedness check, and the results were stored and shown against the file list with a checked flag. Related system tags found by the AI were applied to files automatically. An Ask AI again control was added so reviewers could rerun a check and compare outputs.

File formats were the next problem. Support was extended step by step for Excel, Word, TXT, and PDF content, with the file name shown in the AI modal. Parsing differed between formats, so prompts and parsing were adjusted after comparing outputs against manually reviewed engagement files. Chat summarization was tested and its prompt revised to strip names, IDs, and HTML tags. When a file was judged unrelated, the system now sends the client a message about it.

File handling was tightened through the template library. Files can be labeled with special tags, client and firm uploads are separated, name validation and content hashing were added to uploads, and download errors were fixed. Request file lists update automatically after a template upload, and import and export now carry the request due date and preserve descriptions.

The permission model was rebuilt around engagement-level and request-level roles. Readonly users on an engagement are shown as readonly inside every request, readonly access blocks uploads and editing with a clear hint, and production errors around readonly lists were fixed one by one. Engagement statuses were reduced to Active, Canceled, Test, and Completed, filters now default to Active, and engagements can be transferred between departments. Role changes, including a downgrade rule that blocks an admin from downgrading themselves, were added to user management.

Request handling changed as well: accepted and fulfilled requests are excluded from overdue statistics, request history records who created the request and when, and comments gained a simple editor with deletable messages where a client can delete only the same day. Dashboard statistics were separated into a lighter calculation path so pages load faster, and search was moved from exact matches to partial matching across requests, files, and users. Date handling was corrected so MM/DD/YYYY entries no longer save the day before, and log entries show one consistent date format.

Production issues such as engagement states showing inactive while active, requests not loading on first access, and assistant dashboard filters were each traced and fixed, and a demo with the full feature set was prepared in October 2024.

Line 246 - What advancement did you achieve or attempt to achieve?

counting...

Ephorm Audit now judges uploaded files against their request with an AI-assisted validation step. Prompt logic, tag descriptions, and per-tag relatedness checks turn each file into a related, unrelated, or partial verdict, and the verdict is stored against the file list, with related system tags applied to the files automatically. The same checks run across Excel, Word, TXT, and PDF content, and clients receive a system message when a file is judged unrelated.

File exchange was reworked around the template library. Uploads are validated by name and content hash, client and firm files are separated and filterable, and template-based requests import into engagements with their due date and description preserved.

The permission model now resolves engagement-level and request-level roles against a consistent readonly rule: a readonly user sees readonly everywhere, uploads and edits are blocked with a hint, and role changes run through one user-management flow, including the rule that an admin cannot downgrade themselves.

Engagement state and search advanced as well. Four engagement statuses with an Active-default filter replaced loose state handling, overdue statistics exclude accepted and fulfilled requests, statistics are calculated on a lighter path, and search matches partial text across requests, files, and users.

Open questions remain. Whether AI classifications stay consistent across complex audit datasets, whether file operations hold up at larger engagement volumes, and whether readonly rules cover every edge case are all still under investigation.
