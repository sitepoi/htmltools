Recurring Task Manager - Development Plan

Idea backlog with value scores, effort and requirements - so we can decide what to apply and in which order.
How to read this plan:
  • Value = the colored score box on each card (1-10). 8-10 green = high impact, 6-7 amber = worthwhile, 1-5 gray = nice to have.
  • Effort = Small (hours), Medium (a day or two), Large (multi-day or needs a decision).
  • Requirement = "pure code" means we can build it inside this tool. "CMS" means the parent CMS must cooperate (permissions, storage, notifications, file access). "CMS-AI" means the CMS must provide an AI endpoint because this tool sandbox cannot call the network itself.
  • Use the filters to sort by value, to see only one category, or only simplification ideas.
About AI in this tool: the html-tool sandbox has no network access (no fetch, no API keys), so the tool itself cannot call an AI model. AI is still possible when the parent CMS provides an AI assist endpoint (the CMS calls the model and returns text to the tool, the tool only displays it). That is why every AI idea below is marked CMS-AI. The highest-value AI ideas are conversation summaries and a "what was left behind" summary, because managers and operators read those weekly.
