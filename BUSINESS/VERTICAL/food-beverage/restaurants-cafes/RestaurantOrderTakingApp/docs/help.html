Restaurant Order Taking App - Help

User help for Restaurant Order Taking App. The single source of truth for how this tool works is its SSOT document (SSOT) - this file explains the same behavior for end users, in plain words. Generated from the tool code + SSOT + AI chat by scripts/generate-docs.js. Updated: 2026-10-30.

1. Overview

Restaurant Order Taking App is the live board where your restaurant staff watch all of today's orders and move them forward - accept, start prep, mark ready, complete - with one tap per step.

It is for the kitchen and the front desk of any restaurant that takes orders through the CMS: whoever needs to see new orders arrive and react to them fast. It works on a computer, a tablet or a phone.

2. Before you start

  • An administrator must have mounted the tool on the order application and granted it object access (Object CRUD + the restaurant-orders type in the field settings). If the board shows a configuration banner, ask the administrator to complete these two settings.
  • You can watch the board with viewer rights; changing order statuses needs editor rights on the order application.
  • Open the tool from the order application - the board loads the day's orders automatically and keeps itself refreshed.

3. Step by step

  1. Watch the board. Tabs split orders into All, New, In progress, Ready and Finished, each with a live count. Every card shows the channel (delivery, pickup, dine-in), the customer or table, the waiting clock and the total.
  2. Accept a new order. Click Accept on a new card. Pick a quick time (15-120 minutes) or type custom minutes, watch the button recompute ("ACCEPT 2:55 PM"), then click it. In a hurry, click Accept now for no estimate.
  3. Move the order along. Accepted -> Start prep; in preparation -> Mark ready; ready -> Complete. One tap each, right on the card.
  4. Decline or cancel carefully. Decline (new orders) and Cancel (accepted or later) need two taps: the first arms the button for a few seconds, the second confirms. Use Keep to back out.
  5. Open the details as a popup. Click anywhere on a card for the full order in a popup on top of the board - the list stays visible behind it. You get the customer and address, the phone number to call, timing with the live countdown, payment, items with modifiers and instructions, totals and the internal note. Close with Back, the X, clicking outside, or Esc. Open in CMS jumps to the full record.
  6. Find an order. Use the search box for order number, customer name, phone, table or address, and the sort menu to order the board by longest waiting, newest, or highest total.

4. Common questions

QuestionAnswer
Which orders appear on the board?Every active order (new, accepted, in preparation, ready) no matter when it was placed, plus finished orders whose status changed today. Finished orders from previous days are not shown.
Where do completed orders go?Straight into the Finished tab the moment you complete them - you never lose sight of an order you just finished. They stay there for the rest of the day.
Why does an order from yesterday still show?Because it is still active - a stuck order still needs the kitchen. And an order placed yesterday but finished today stays visible in Finished for the day.
What do the card and tab colors mean?Each status has its own soft color (amber for new, blue for accepted, orange for in preparation, green for ready and completed, red for declined, gray for cancelled). Time remaining overrides it: the last 5 minutes turn amber, late orders turn red, and a new order waiting too long turns red.
What does the red highlight on a new order mean?The order has been waiting longer than the warning threshold (default 10 minutes) without being accepted. Accept or decline it soon.
What happens to the estimated time after accept?It is shown on the card as "est. ready time" or "est. delivery time" with a live countdown ("in 12:30"). Past the target the card turns red and shows "LATE 3:20". It persists across refreshes when the order type has the estimatedReadyAt field.
Why do amounts show a dollar sign?So they read as money. The default currency is USD; an administrator can set the currencyCode parameter (for example EUR or TRY) for the restaurant.
Can I undo a status change?Not directly - the workflow only moves forward, with decline and cancel as separate steps. Use the two-step confirm for those.
Who can change statuses?Editors and managers. Viewers can watch and search but see no write buttons.
How live is the board?It refreshes itself every 20 seconds by default, refreshes when the tab becomes visible again, and the waiting clock ticks every second. Use the Refresh button anytime.

5. Troubleshooting

ProblemWhat to do
The board shows "Could not load orders"Click Try again. If it keeps failing, ask an administrator to check the Object CRUD setting and the restaurant-orders entry in the field settings.
A configuration banner is shown above the boardObject access is not configured. Ask an administrator to enable Object CRUD and add the order type (scope shared).
The buttons are missing or read-onlyYour role is viewer, or the form is in read-only mode. The read-only banner explains it.
The estimate disappears after a refreshThe order type probably does not have the estimatedReadyAt field yet. The status change itself is saved correctly; ask an administrator to add the field for full timing.
Two of us changed the same orderThe last change wins and the next refresh shows the final state - there is no locking between two open boards.
Nothing new appearsCheck that auto refresh is not turned off (autoRefreshSeconds = 0) and use the Refresh button manually.
