The problem

Orders live inside CMS records, not on a board

Before this tool, the order application only had a detail view per record. Watching the day meant opening each order one by one in the CMS object manager.

  • No single view of all waiting orders
  • No way to notice a new order arriving
  • Every status change = open a record, click, save, repeat
The solution

One board for the whole day

The board loads every order of the day through the CMS and keeps itself fresh - polling, visibility refresh and a ticking waiting clock on every card.

See everything

Tabs with live counts: All, New, In progress, Ready, Finished.

Act in one tap

Accept, start prep, mark ready, complete - straight from the card.

Why it matters

Built for a busy kitchen

Nothing waits unnoticed

New orders toast and flash; long-waiting orders turn red.

Promises stay visible

Accept with an estimated ready or delivery time that stays on the card.

Zero setup data work

It reads the very same order records the widget writes - no migration.

Highlights

What the kitchen gets

  • Waiting clock on every card - mm:ss, then hours and minutes
  • Accept dialog with 15-120 min chips and a live "ACCEPT (2:55 PM)" button
  • Two-step confirm for decline and cancel - no accidental destructive taps
  • Search by name, phone, table or address; three sort modes
